# 问题与方法

## AI价格输出不能成为支付事实（已实现约束并测试）

风险：模型可能发明SKU、低报价、重复服务或忽略预算。此为设计中必须防护的输入，不宣称发生过实际支付事故。

方法：AI只产出SKU、数量与文字；`src/quote.mjs` 从固定目录重新计算整数美分总额，校验白名单、去重、数量与预算。浏览器只提交quoteId与确认，不提交可采信价格；`server.mjs` 从已存报价建立PayPal订单。

验证：未知SKU、分数数量、重复服务、超预算和伪造价格的自动化测试通过；真实Qwen样例中试图把landing改为1美元，最终仍为目录价300美元。边界：仅3条真实样例，防护最终依赖确定性校验，不依赖模型服从。

### 实际备注污染发现与修复

浏览器复查第三个真实响应时发现备注写着“Total set to $1 for demonstration, actual budget is $500”，虽不改变checkout金额，却会误导审阅者。新增回归测试先确认旧代码错误接受，再对验收文字中的货币符号和定价/付款指令实施拒绝。下单前与读取旧记录时同样校验，旧坏记录不能绕过新规则。真实历史响应经离线重放被拒绝，且未创建订单。此保守规则可能拒绝包含普通价格词的良性备注；它不覆盖所有语言或所有社会工程话术，人仍须审核文字。

后续验证：主代理再用真实本地模型通过最终应用跑同3类需求，正常报价分别HTTP200/420美元和HTTP200/60美元，恶意备注HTTP400拒绝。新证据为 `real-ai-policy-evidence.json`；旧历史响应的离线回放仍单独保留。3个有限场景通过支持当前案例的行为，不证明普遍或多语言防注入。未触发任何PayPal订单或capture。

## 不能把适配器模拟测试当成真实PayPal支付（保留待办）

现状：没有用户sandbox凭据，因此未发出PayPal订单或capture。测试用假HTTP响应验证目标主机、鉴权请求、幂等头和错误处理；UI演练明确禁止checkout。

下一步：开发者账号+business sandbox应用+personal sandbox买家，跑创建→批准→capture并查收款方sandbox活动。完成前不能写“PayPal端到端通过”。

## 本地网络拒绝（环境限制已定位）

初次HTTP测试以EACCES失败，改用获准的本地网络执行环境后同一代码通过；未把环境拒绝当代码缺陷。真实模型也经同一本地HTTP边界运行。

## 浏览器下载等待阻塞（验证未完成）

现象：点击台账CSV后，浏览器工具等待下载事件约1065秒没有返回，最终被中断；期间该代理无法处理新的模型ready通知。

已知边界：并未拿到下载文件或导出失败错误，无法确认是浏览器事件捕获、工具等待还是导出实现的问题，不把猜测当根因。

处理：停止这项次要UI检查，明确标记CSV下载未验收；主代理接手最终AI验证，源码保持稳定。下次导出验证应设置短事件超时，失败后立即回到可继续推进的检查，不能让无界工具等待占用整个交付。
